# 动画预规划与兼容性

## 编排前置
在图稿阶段划分背景、主要动作单元、独立文字层、遮挡层、终态位置；记录每步 `trigger/target/effect/start/duration/end_state/dependency`。静态设计必须为移入/移出/遮罩预留画面。

## 动画设计层级
- 信息型：按阅读顺序分组揭示，避免一行一动造成冗余。
- 结构型：局部展开、对比滑移、分层剖示、过程箭头，使用软件可支持的真实对象。
- 场景型：多层景深/对象转换/章节转场；必须验证在目标客户端的细节。
- 无动画型：讲课/打印/纯PDF场景可跳过动画；不强制增添。

## 检查四阶段
1. Design：预规划并冻结对象身份、入场/终态。
2. Build：按用户要求**实装**真正可播放的动画；动作设计表仅为内部计划或经用户接受的降级交付，不得替代动画。
3. Inspect：检查PPTX时间轴、对象引用、开始/结束状态。
4. Play：PowerPoint/WPS目标版本实播，观察帧间遮挡、字体、布局与性能。

### 不夸大能力
XML中存在 `p:timing` 只表明文件里有时间节点，不保证软件播放兼容；无法实播时记录 `not_tested`。需要流体墨迹、逐笔书写等难以由PPT对象原生实现的复杂效果，先尝试兼容技术替代；未经用户同意，不得将真实动画降级为视频、静态图或动作设计表。声明每种替代的编辑性与软件兼容风险。

## 用户确认的降级边界（v2.3）

- 仅逐元素编辑、不要动画的 A 项目：跳过动画制作及实播测试，不能为了套流程强加动画。
- 明确要求动画的 A 项目：成功定义为**实装并能在约定目标软件播放**；只能验证 XML 时不得称“可播放”；缺少目标客户端时写“未实播”。
- 同一技术手段反复失败时尝试其他有权限的方法；无法实装或需要替换成视频/静态/脚本，**先获取用户的明确接受**。未批准不得把该项目标记为“全部达标”。
