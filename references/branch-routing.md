# A/B → B1/B2 两级路由与状态机（v2.2）

## 触发条件及措辞

仅**新建 PPT**触发一次。优先于任何检索、提纲、8 套风格生成、工作量估计、图稿批量生产。请向用户原样或等效表达：

> 本次 PPT 是否需要动效或动画？
>
> **A：需要**。使用原流程：8 套视觉方案 → 选风格 → 全套图稿审核 → 可编辑拼装 → 动画制作与 QA。
>
> **B：不需要**。进入独立的图片路线：先生成同一页的 B1 无约束/B2 固定画质约束的两张预览，再等待用户确认 B1、B2 或默认双套生成；不进入 A 的 8 套预览、全稿审批与可编辑分层。

不能把 B 说成“画面质量必然更高”；不能诱导用户在要求对象编辑时误选 B。
不要用“你有什么主题、页数等”抢在 A/B 前面。用户只选了 A/B 而未给主题，可在该选项之后补问**必需**的关键字段。

## 路由表

| 任务类型 | 是否询问 | 正确做法 |
|---|---|---|
| 从零生成 PPT、用户未明确 A/B | 必问 | 停在初始 Gate，待选择 |
| 用户在本次请求明确选择 A/B | 不再问 | 直接进入该分支 |
| 用户说“无动画”但没有选择 A/B | 问一次、突出 B 推荐 | 不替用户做最终决定 |
| 用户说“要动画”但没有选择 A/B | 问一次、说明 A 对应 | 不默认为 A |
| 正在续作、状态中已有分支决定 | 不再问 | 沿原分支继续 |
| 只修订、检查或拼装已有确认素材 | 不强制重新选 | 执行受影响步骤 |
| 由 B 改选 A | 需要记录用户变更 | 不假称现有图像自动变可编辑、需进入 A 的确认步骤 |
| 由 A 改选 B | 需要记录用户变更 | 不再执行 A 的未完成 Gate，保存既有成果，可复用已有合格图稿 |

## 状态与优先级

在 `project.json` 里记录 `workflow_branch`、`gates.branch_selected`、`brief.animation_requested`，按模板实例初始化。**持久化后续作沿用，不因新的聊天自动重问**。

- A 使用 `brief/styles/selected/pilot/artwork/approved/build/qa/delivered`，遵守原预览与图稿审批 Gate。
- B 使用 `b_preview → b_await_confirmation → image_generate → image_qa → image_delivered`。其中预览两张必须使用同一代表性页面；用户确认前不得进入 `image_generate`。用户仅回复“按默认/开始/确认”视为授权 `both`，不是选完 B 就自动授权。每页每版本独立生成、检查、交付；未要求 PPTX 时不做格式拼装。
- A、B 都必须在用户作出分支选择之后才进入生成阶段。
- 用户指令优先，分支选择不能替代版权、事实准确性和交付物真实性。

## B 的二级选择 Gate

选择 B 并确认主题等生成两张对照预览的必要信息后，生成 B1/B2 同一页的两张独立高质量预览。B1 不叠加额外视觉风格/画质约束；B2 只追加固定原文：

> 画面保持干净自然的真实照片质感：不要数字噪点与彩色噪点，不要颗粒覆盖，不要过度锐化，不要 HDR 与油腻高光，不要蜡质表面，不要脏灰色调，不要假细节与压缩伪影。

**预览之后必须原句提示**：

> 可选择仅开始 B1 分支或者仅开始 B2 分支，默认是同时开始 B1 和 B2 生成。

等待用户回复“仅 B1”“仅 B2”“两个都做”“按默认/开始/确认”。“按默认/开始/确认”在两张图片**已真实展示**之后才合法地解析为 `both`。不能先用默认值自动开始。

建议持久化 `b_previews: {slide_id, B1, B2}`、`b_generation_mode: null | "B1" | "B2" | "both"`、`gates.b_previews_generated`、`gates.b_variant_confirmed` 和每页 `variant_images`/`variant_qa`。`both` = 每页 2 个文件，文件分别在 `B1/`、`B2/` 目录；每个版本必须完成全套及自身的质量检查。已完成的项目按原有分支继续，不重复引导。
